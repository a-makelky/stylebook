## The three open questions

The public docs used below were fetched on 2026-10-02.

1. **How long after `fork()` returns does `get()` report `FORK_IN_PROGRESS`, if at all?**

   It did not report it. On both new copies, `afterFork.codes` is empty, `attempts` is 1, and `elapsedMs` is 48 and 50. That duration is the successful `get()` itself, measured from the moment `fork()` returned. There was no retry and no sleep.

   [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/) says `get()` throws if the repo is not ready yet. The generated types name that code `FORK_IN_PROGRESS`. They do not say how long the not-ready window lasts. On this run it was already over, if it existed at all, by the time `fork()` returned to the Worker.

2. **Does `info().source` on a copy read `artifacts:<namespace>/library`?**

   Yes. Both copies returned `artifacts:stylebook-demo/library`.

   The generated `ArtifactsRepoInfo.source` comment gives the example `artifacts:namespace/repo`. The [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/) page describes `info()` but does not show that string. The [REST API](https://developers.cloudflare.com/artifacts/api/rest-api/) example for getting a repo shows `"source": null` for a repo that is not a copy. The generated types and the live service agree with each other.

3. **Does a copy made with `defaultBranchOnly: true` carry the library's full history on `main`?**

   Yes, for this library. Call 2's copy lists both editions, with the same ids as the library, newest first. This was not a single-tip copy.

   `fork()` takes `defaultBranchOnly` on the [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/). The [best practices](https://developers.cloudflare.com/artifacts/concepts/best-practices/) example passes `true` and does not say whether that keeps every edition on the default line. The generated types say the default is `true` and do not define how much history is copied. The only history read here is `main`, which is the only line this library has. Other lines were not checked.

## Where the docs are silent, and what the stand-in does

Writes still go through Git because the binding reads files and does not write them. That path is the one in the [isomorphic-git example](https://developers.cloudflare.com/artifacts/examples/isomorphic-git/) and the [Workers get-started guide](https://developers.cloudflare.com/artifacts/get-started/workers/). The tracer's `savedAt` values end in `.000Z` because `log()` returns `authoredAt` in unix seconds (generated `ArtifactsCommitMetadata`) and the Worker multiplies by 1000.

The local stand-in already matched this run: source string `artifacts:<namespace>/library`, a new copy ready on the first `get()`, and both editions present on the copy. No behavior change was required. The comment in `test/fake-artifacts.ts` that called immediate readiness a guess now points at this log. The stand-in can still throw `FORK_IN_PROGRESS` when a test asks it to, because the generated types still list that code.
